## 결론 요약

**이 앱의 유일한 차별점이 실제로는 구현되어 있지 않습니다.**

심판은 "인용이 원문에 존재하는가"만 검사하고 **"답변이 그 인용으로 뒷받침되는가"는 검사하지 않습니다.** 원문이 "정확도가 10% 하락했다"인데 답변이 "정확도가 99% 상승했다"여도, 인용 ID만 올바르면 통과합니다(코드 검토 #1, 재현 확인됨).

이것이 제품 문제인 이유: **인용이 붙어 있으면 사용자는 확인을 건너뜁니다.** 확인을 요구하는 도구보다, 확인을 건너뛰게 만들면서 틀릴 수 있는 도구가 더 나쁩니다.

두 검토가 같은 곳으로 수렴했습니다.

| | 지적 |
| --- | --- |
| 코드 검토 #1 | 심판이 인용의 **존재**만 보고 **뒷받침**은 안 본다 |
| 제품 검토 마지막 | "틀린 인용을 자신 있게 통과시키면 전환율 개선은 일시적" |

**합의된 순서: 이 결함을 먼저 고치고, 그다음 화면을 고친다.**

## 1라운드 — GPT의 제품 비판

### 판정: 현재 상태로는 월 2만원 범용 연구 SaaS로 팔기 어렵다

**작업 흐름의 이탈 지점 네 곳**

| 지점 | 문제 |
| --- | --- |
| 입구 | 무료 사용에 Gemini 키 발급을 요구 → 효용 보기 전 이탈 |
| 자료 투입 | arXiv 검색·Markdown 업로드 중심 → 이미 PDF를 모아둔 사용자를 못 받음 |
| 노트 정리 | 파서가 특정 절 제목을 요구 → "내가 이미 정리했는데 뭘 더 해주지?" |
| 검토 | 논문 20편 × 항목 6개 = 120셀 → **일을 줄이는 게 아니라 새 업무 창출** |

**가장 아픈 지적**

> **"노트에 없는 내용"과 "논문에 없는 내용"은 다릅니다.**
> 노트 기반 추론을 논문 원문에 대한 판단처럼 받아들이게 하면 제품 효용 자체를 오해하게 됩니다.

**차별점 평가**

NotebookLM은 출처 기반 답변과 인용을 제공하고, Elicit은 무료 등급에서도 검색·요약·출처 확인·Zotero 가져오기를 제공합니다. **"근거를 표시한다"만으로는 차별화가 약합니다.**

"없다고 말하기"는 틀린 실험 조건 인용을 막아준다면 가치가 있지만, **초록만 읽고 계속 "없음"이라 하면 무능한 앱으로 느껴집니다.**

**과잉으로 지목된 것**

- 검색 질의 사전 검토 — 첫 결과 전에 사용자를 검색 설계자로 만듦
- 절·버전·workspace 개념의 전면 노출
- 전 셀 검토를 유도하는 흐름
- **평가 루프의 상품화** — 내부 품질 도구이지 판매 문구가 아님

> 사용자에게 즉시 돌아오는 반영 없이 채점부터 요구하면 **무료 데이터 노동**으로 느껴집니다.

## 2라운드 — Claude의 반론과 구체안

### 동의한 것

1. 노트/논문 부재 혼동 — 가장 아픈 지적, 반박 없음
2. BYOK를 입구에 둔 것 — 제가 제안했으나 온보딩 관점을 놓침
3. 120셀 검토 = 새 업무
4. 평가 루프는 개발 도구
5. PDF/Zotero 입구 부재

### 반박

**"근거 표시는 NotebookLM/Elicit도 한다"** — 절반만 동의.

그들은 인용을 붙이되 **여전히 종합(synthesize)합니다.** 이 앱은 종합을 거부하고 심판이 인용 없는 문장을 서버에서 버립니다. 다만 사용자가 체감하는 건 "답이 적은 앱"일 수 있습니다.

→ **차별점은 "근거를 붙인다"가 아니라 "내가 다시 확인할 필요가 없다"여야 합니다.** 그리고 그건 검증 시간 감소로 증명해야 하는데, 아직 증거가 없습니다.

### 제시한 4개 안과 GPT의 판정

| 안 | 내용 | 판정 |
| --- | --- | --- |
| **C** | 첫 화면을 "논문 5편 → 비교표" 한 단계로 | **가장 큼** — 첫 3분 안에 결과를 보면 활성화율이 바뀜 |
| **D** | 무료 등급에서 BYOK 제거, 운영자 키로 월 5회 | **큼** — 단 비용 통제·악용 방지 필요 |
| **A** | 3단계 부재 구분(논문에 없음/읽은 범위에 없음/원문 미확보) | 중간 — 신뢰·재사용률은 올리나 **첫 전환율 영향 적음.** 문구만 바꾸면 표면 개선 |
| **B** | 전 셀 검토 → 불확실한 5개만 | **위험** — 심판이 확신한 오답을 검토에서 제외함 |

**우선순위: C → D → A → B**

### 버릴 것 / 남길 것

| | 판정 |
| --- | --- |
| Seed 검색 | 버리지 말 것. "논문을 못 가진 사용자용 유입 경로"로 **첫 화면에서만 내림** |
| 노트 라이브러리 | 유지. 단 **입력물이 아니라 비교표의 근거 저장소**로 역할 변경 |
| 평가 루프 | 유지하되 **사용자 기능에서 숨김**. 제품 메시지로 쓰지 말 것 |
| **노트 업로드를 선행 조건으로 만드는 흐름** | **제거 후보.** 사용자는 노트를 만들러 오는 게 아니라 비교 판단을 하러 옴 |

### 검증 시간 감소 측정 설계 (사용자 5명)

동일 질문을 두 방식으로 처리, 순서 효과 제거를 위해 절반은 A→B, 절반은 B→A.

- **A**: 기존 방식 (PDF·검색 도구만)
- **B**: 앱 비교표 사용

기록 항목: ① 결론까지 걸린 시간 ② 원문 재열람 횟수 ③ 결론 변경 횟수 ④ 근거 없는 주장 수 ⑤ 재검증 필요 표시 셀 수 ⑥ "보고서에 써도 되는가" 1~5점

**핵심 지표**

> **검증 완료 결론 1개를 얻는 데 걸린 시간**

시간이 줄어도 검증된 결론 수가 줄면 실패. 5명으로 통계적 증명은 불가하나, **중앙값 30% 이상 감소 + 신뢰도 하락 없음**이면 다음 단계 근거.

### 과금 모델

**구독보다 프로젝트 단위가 더 자연스러움.** 구매 단위가 "매달 AI를 쓴다"가 아니라 **"이번 문헌고찰을 끝낸다"** 에 가깝기 때문.

```
무료 비교 프로젝트 1회
  → 프로젝트당 유료 결제
    → 반복 사용 확인 시 개인 구독
      → 공동 라이브러리·보안 필요 시 랩 라이선스
```

## 3라운드 — 핵심 결함을 어떻게 메울 것인가

세 후보를 놓고 물었습니다.

| 안 | 내용 | 실패 모드 | 비개발자 1인 감당 |
| --- | --- | --- | --- |
| **(a)** | **자유 서술 폐지, 추출형만** — 답변란에 원문 문장 그대로 | 원문이 잘려 문맥 왜곡 가능 | **가능** |
| (b) | 자유 서술 + 별도 모델로 함의 검사 | 검사 모델도 틀림. 비용·지연·디버깅 부담 | **부적합** |
| (c) | 자유 서술 + 인용을 답변 옆에 강제 노출 | **사용자가 실제로 대조하지 않음.** 인용이 오히려 잘못된 신뢰를 강화 | 쉬우나 약속 미보장 |

### GPT의 선택: (a) 추출형만 허용

**(a)를 택하면 제품이 무엇이 되는가**

> "AI가 요약해준다"가 아니라 **"원문 근거를 항목별로 정렬·비교해주는 검증 도구"**.
> 월 2만원 가능. 오히려 **"그럴듯한 요약"보다 틀릴 수 있는 부분을 숨기지 않는다**는 점이 명확해져 신뢰를 얻기 쉬움.
> 단, 핵심 가치는 문장 추출 자체가 아니라 **여러 자료에서 관련 문장을 같은 기준으로 나란히 보여주는 것**에 있어야 함.

### 순서에 대한 최종 판정

> **C(비교표 화면)보다 결함 수정이 먼저.**
> 비교표가 아무리 보기 좋아도 근거와 답변의 연결이 틀리면 핵심 약속이 무너집니다. 먼저 추출형으로 신뢰 가능한 최소 제품을 만들고, 그다음 그 문장들을 비교표에 배치해야 합니다.
> **그래야 화면 개선이 잘못된 확신을 더 빠르게 확산시키는 일이 없습니다.**

## Claude의 유보 사항

이 문서는 합의된 내용을 기록한 것이며, 다음은 아직 확인되지 않았습니다.

- **경쟁 제품 비교는 실사용 검증이 아닙니다.** NotebookLM·Elicit의 실제 동작을 이 세션에서 대조하지 않았습니다.
- **"추출형이 월 2만원짜리인가"는 검증되지 않은 판단입니다.** 5명 실험 전에는 양쪽 모두 추정입니다.
- **(a)로 전환하면 잃는 것이 있습니다.** 여러 문장을 종합해야 답할 수 있는 질문("이 논문들의 공통 한계는?")은 추출형으로 답할 수 없습니다. GPT는 이 손실을 명시적으로 다루지 않았습니다. 전환 시 **어떤 질문 유형을 포기하는지** 먼저 목록화해야 합니다.
- 코드 검토의 나머지 지적(#2, #4, #10~#13)은 아직 대조·수정하지 않았습니다.
